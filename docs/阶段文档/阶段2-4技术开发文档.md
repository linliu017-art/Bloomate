# 阶段2-4技术开发文档：目标步骤调整

## 范围及关联
依 PRD V3 FR04 与第二轮能力图，实现目标计划中一个未完成步骤的 AI 调整建议：填写困难、后台持久化生成任务、查看原步骤和建议、编辑后明确确认或放弃。AI 无权直接写正式计划。用户未选择的步骤、已完成成果、习惯周期、种植和其他植物不变；计划变更及其前后版本存档；重试确认幂等。日期、频率的习惯调整、暂停和阶段成长列为后续子阶段，不能冒称本阶段已实现。

## 技术与约束
沿用 FastAPI、Pydantic、SQLite、Next.js 和 DeepSeek，模型密钥、预算及超时规则沿用现有配置。新增带 owner 的持久化调整提案表；异步任务 pending/running/done/error，重启时中断未完成任务并提示重试，保留已生成提案。按植物 + 已确认原计划 + 步骤完成记录计算基准指纹，确认时事务内再次检查；原计划或任何已确认步骤状态变动后拒绝旧提案，避免覆盖；目标步骤已完成不可调整。旧计划不预先迁移、不删除。

## 接口与模型
- POST `/api/v1/plants/{plant_id}/adjustments`：输入严格合法的 `step_index`、非空困难描述，记录原步骤和基准后返回提案 ID，后台通过已有模型通道生成单项建议。
- GET `/api/v1/adjustments/{id}`：返回状态、原步骤、建议、错误，按 owner 过滤。
- POST `/api/v1/adjustments/{id}/confirm`：用户确认具体建议（可编辑），事务校验基准与待办状态、替换单个步骤、保存前后值和提案状态；重复提交不再次修改；已放弃或旧版本拒绝。
- POST `/api/v1/adjustments/{id}/discard`：仅放弃提案，不改正式计划；重复放弃幂等。
所有请求与响应、统一错误经校验；生成保持已有超时、有限重试、服务端密钥、预算预留；模型无法独自提交，日志不保存完整用户文档。

## 界面和验证
保留的网页在目标步骤中提供调整入口与困难输入；展示变更前后、未受影响说明、编辑及确认/放弃；任务发生变化时提示重新生成。目标、习惯原功能必须回归；离线替身验证提案不改计划、确认、放弃、完成后不允许改、状态/计划并发冲突、旧提案、重复提交、重启恢复和归属；真实 DeepSeek 用虚构目标生成建议并确认；重启钩子覆盖提案及确认记录。桌面与手机检查及 `verify.sh Bloomate 阶段2-4`。暂不安排对外试用与上云。
