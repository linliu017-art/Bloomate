## 1. 原始需求（逐字保留，不改写）

我们要做一款**以花园养成为游戏表现的 Personal Agent**，面向希望持续推进个人目标的用户。AI 以园丁伙伴的形象，帮助用户把模糊想法变成可执行的计划，并通过花园成长呈现现实中的进展。
**AI 伙伴的功能**
用户可以通过对话提出目标，例如“一个月内准备好产品经理面试”。AI 了解用户的基础、可用时间和截止日期，将目标拆成阶段与任务。在用户允许的范围内，记住目标、偏好和执行记录，创建或调整待办；根据完成情况和用户反馈，帮助缩小任务、解决阻碍、重新安排计划。后续可以接入日历、笔记等工具。
**花园的游戏机制**
每个长期目标对应一株植物，从种子开始，随着相关任务完成，逐步发芽、长叶、开花。完成整个目标后，植物成为永久收藏，保留在花园和图鉴中，点击可以回看对应的目标、完成时间和成果。
用户还可以通过阶段成果解锁新花种和花园装饰。暂停目标时植物休眠，恢复后继续成长，避免因为中断而失去已有积累。
**日常使用流程**
用户与园丁伙伴交流，查看今天要做的任务；完成任务后，获得短暂的成长动画和奖励反馈。遇到困难时，可以直接说“这件事太难了”或“这周没时间”，由 AI 协助调整。定期复盘时，用户既能看到现实目标的进展，也能看到花园逐渐丰富。
**第一版范围**
先实现目标与待办管理、AI 拆解和调整计划、必要的个人记忆，以及固定花位、少量花种、生长动画和收藏图鉴。采用简单的 2D 花园，暂不加入自由建造、复杂经营和社交玩法。
产品面向正式发布和后续商业化，先验证用户是否持续通过它推进目标，再探索进阶 AI 服务、花种外观和花园主题等付费内容。
**核心体验是：一个逐渐了解你的 AI 伙伴，陪你把目标做成，并把这些真实成果留在一座持续生长的花园里。**

### 2.3 需要验证的假设

H1：主要困难包含目标模糊、任务过大与安排失衡，AI 调整能提高实际推进率。当前只有产品设想支持，尚无用户证据。

H2：花园能帮助用户理解积累、在中断后回来，效果超过首次使用的新鲜感。需观察持续使用和访谈，不能用动画播放次数证明。

H3：必要记忆能减少重复解释并改善计划，而不会让用户觉得被过度记录。需记录记忆纠错、删除与用户反馈。

### 2.4 首版旅程

1. 新用户无需先注册即可选择「完成一个目标」或「培养一个习惯」，也可先对话由 AI 建议类型、用户确认；可跳过装饰介绍。游客态持续说明「当前为体验，尚未保存到账户」。
2. 明确目标补问完成标准、基础、可用时间和期限；习惯线收集行为、单次完成标准、阶段起止日期与执行频率。用户提议选择时间范围并每天打卡；允许非每日频率为建议。未知信息保留未知。
3. 显示阶段、任务、预计投入和首个行动。用户可逐项编辑，一次确认整份计划后保存并种下种子；游客保存到临时体验空间，已登录用户保存到账户。第一株种下后邀请「注册并保存我的花园」，不把注册放在首次价值体验之前。
4. 每日进入可先看今日待办，也可直接对话；点植物进入对应目标，查看下一步与已有成果。
5. 用户点任务「完成」或习惯「打卡」即提交明确完成指令。保存成功后给轻反馈；达到已约定阶段成果才发生明显植物变化，不额外确认普通任务。
6. 说「太难了」「这周没时间」时，显示变更前后差异、影响和待确认问题；接受后才更新安排。
7. 暂停时进入休眠；恢复时保留进度，并预览新的日期安排。过期任务不会自动批量挪到今天。
8. 用户可主动复盘；园丁也会根据执行记录发现可能停滞，主动留下关心与调整建议，下次打开可看到。明确目标完成后整株收藏；习惯阶段里程碑开花并保存阶段收藏，同株继续生长。阶段到期先复盘，不自动算达成。

### 3.1 状态与变更共用规则（建议）

- 正式计划与 AI 提案分开。提案包含基准版本、受影响目标、变更前后值与理由；用户可编辑后确认。确认按钮绑定具体提案，新的模型回复不能沿用旧确认。
- 用户手动点击完成、修改日期等即是对应动作的授权；AI 自主提出的改动需要预览确认。目标结束、批量删除、记忆授权分别明确呈现后果。
- 目标状态：草稿 → 进行中 ↔ 暂停；进行中或暂停 → 用户确认完成；未完成目标可归档。归档不冒充完成、不产生开花收藏。
- 任务状态：待做、进行中、完成、取消；受阻为附加信息，不当成完成。暂停继承目标状态。V2 将重复习惯独立为习惯定义、阶段周期和打卡实例，不与一次性任务混用；暂停期间不产生应完成实例。
- 同一目标的计划、任务、成长记录使用同一提交边界；重试不产生第二份结果。跨设备版本冲突时展示最新状态，让用户重新确认。
- 撤销误点允许纠正完成与成长；这是用户主动改正，不是系统因停用惩罚。若撤销使目标不再完成，撤销收藏完成状态并保留历史，后续完成仍使用同一株植物。

### 3.2 成长与奖励（V2 更新；阶段重反馈与标准确认方式已确定）

明确目标规划确认时建立固定总量的成长份额，按阶段和任务分配。用户完成任务后获得其份额，仅给轻量反馈；明显发芽、长叶等变化绑定确认计划中的阶段成果。任务拆分时子任务合计继承父任务剩余份额；重复确认、删除任务、AI 生成计划、聊天次数和登录天数均不增加成长。

改计划时保留已赚取份额，只重新分配未赚取部分，并在预览中显示影响。扩大目标范围须说明完成标准变更，不能把既有成果抹掉；彻底换目标应建立新目标。具体成长份额分配仍待体验验证；阶段达成标准在创建时由 AI 提议并由用户确认，不由系统暗中调整。

明确目标线的种子 → 发芽 → 长叶转换由阶段成果驱动，累计份额只辅助呈现阶段内进度；最终开花及整株永久收藏需用户确认目标完成。尚有待办时，用户可完成后继续，或明确确认范围调整并处置剩余待办；不得靠“勾完任意一组任务”自动宣布真实目标达成。

习惯线不设置“整个习惯完成”的总进度条。每阶段依据确认的频率、完成标准和里程碑记录进展，普通打卡轻反馈，阶段里程碑开花并留收藏，原植物继续生长；时间到期本身不产生奖励。

暂停只叠加休眠表现，保留底层成长。固定花位满时仍允许创建草稿或整理展示，不删除目标；明确目标的完成收藏可移出种植位并在固定收藏位展示；习惯阶段收藏不移走原植物，图鉴保留所有阶段。花位、花种、展示位数量待定。

阶段解锁按成果标识去重，撤销误点时同步重算对应资格；再次满足条件不重复发放。已完成目标的留存承诺以账户存续和用户未删除为前提；用户删除权优先于“永久收藏”的表现描述。

### 3.2a 习惯周期与打卡（V2；补签与阶段标准规则已确认）

- 习惯定义长期保留；阶段周期有开始日、结束日、时区、频率、单次完成标准和阶段里程碑。日期必须有效、结束不早于开始；支持自定义时间范围，不宣称固定天数一定养成习惯。
- 例如「未来 30 天每天阅读 20 分钟」。周期长度用于安排和复盘，开花仍看已约定成果；不强制全勤。AI 在创建阶段时提议具体达成标准，由用户修改或确认后保存，例如 30 天内完成 24 天。24/30 是已接受的示例，不是所有习惯硬编码的 80% 门槛；没有确认标准时不得自动判定里程碑达成。
- 每天打卡为用户提出的主流程；建议也支持每周指定日期等频率。非计划日不是漏签。同一习惯默认只有一个进行中的阶段，防止同一次行动被多个阶段重复计奖。
- 每个计划执行日生成稳定实例；用户确认后打卡，重复提交仅一次生效。改频率或时区只影响确认后的未来实例，既往记录不重建；日期按用户时区解释。
- 漏签保留累积成长，不重置植物或已有收藏。已确认允许补签最近 3 天，区分“做了但忘记记录”和“没有做”；只有用户声明确实执行才记录为补签完成。窗口口径按该执行实例的计划时区计算，允许今天之前的 3 个自然日，当日为正常打卡；只能补已有计划实例，不能给暂停日、非计划日或未来日期凭空生成完成。保留实际行动日期、录入时间和补签标识，重复补签不重复计奖。超过窗口不计入补签完成，可在复盘备注事实；阶段已确认收藏后若需纠错，应先进入明确的更正流程。
- 周期结束进入待复盘：查看进展，用户选择进入下一阶段、调整、暂停或归档。未达到约定里程碑不能只因到期就自动收藏，用户改变标准也须明确确认并保留记录。
- 暂停保留阶段与植物；恢复时预览剩余执行日期、截止日期是否调整与里程碑影响，不自动延长周期。

### 3.2b 主动关心（V2；触发与不反复催促已确认）

首版主动联系仅为站内留言，用户不必当时在线。已确认默认在同一目标或习惯连续错过 2 次计划行动后留言一次。以已过执行窗口且未确认完成的实例为依据，不把 2 次行动等同于 2 个自然日；非计划日、取消和暂停不计错过，未定执行时间的待办不纳入。不能仅凭未打开 App 推断现实中没行动，更不能推断用户懒惰或情绪状态。后台检查周期属工程配置，勿扰时段默认值仍待确定。

同一停滞事件只生成一条有效关心，可回应“已经做了”“太难”“最近没时间”“暂停关心”，再进入完成确认或计划预览。发送前重新检查最新状态，已完成、有效补签使连续错过不足 2 次、暂停、关闭关心或进入勿扰时取消不适用的候选。用户未回应时保持本事件已留言状态，不靠冷却到期重复发送；仅查看留言不算回应。用户可关闭或稍后再看；后续恢复行动才重新统计新的连续错过事件，已发送留言保留历史，不重复发送失效提醒。

后台允许读取授权记录、生成关心草稿并写入站内信箱；不能据此自动改日期、标完成、暂停目标或修改记忆授权。模型不可用时可保留候选并稍后有限重试，不发送假称了解用户的内容。不得补发大量过期留言。

### 3.2c 游客体验与绘本风（V3 新增）

已确认体验顺序为：打开 → 园丁对话 → 确认计划 → 种下第一株植物 → 注册保存。注册前持续显示临时状态，保存入口解释账户保存与跨设备恢复的价值，不假称体验已永久保存。

建议游客契约：

- 游客有隔离的临时体验空间，能够真实走通第一株植物与已确认计划；本次上下文可用于对话，但不默认开启跨会话长期偏好提取或离线主动关心。账户迁移成功后再展示对应设置与授权。
- 游客内容可能临时送至服务端和模型完成规划，不能写成「仅在本机」或「不上传」。临时保留时长、过期提示、游客调用额度在工程规格与发布前明确配置；不以未注册为由承诺不处理数据。
- 注册界面可关闭并回到当前体验；注册或保存失败保留仍有效的体验内容与重试入口，不宣称账户保存成功。临时空间过期时明确告知，提供重新开始，不伪造恢复结果。
- 用户选择「注册并保存我的花园」后，确认账户与保存范围，再以一次可重试操作迁移目标或习惯、计划、任务、植物和已有事件。注册成功与迁移成功分别显示；迁移未完成时不得清理源数据。
- 已有账户登录时显示将添加的本次体验内容，用户确认后追加，不覆盖原有花园；重复回调或重试不会重复生成植物与奖励。成功后撤销原游客对已迁移资源的访问。
- 仅对完成迁移并启用相应功能的账户执行跨日主动关心；游客体验不制造长期保存承诺。关闭或退出注册不视为放弃目标，也不让植物枯萎。

绘本风已确认。建议以温暖柔和的色彩、简洁手绘轮廓、轻纸感和自然生长动画表现；正文与按钮保持清楚对比，减少纹理干扰。园丁表达温和、具体，鼓励可执行行动；不用羞辱、强迫签到或装饰遮挡任务。具体视觉稿、角色造型和资源数量尚未设计，不把描述当作已完成素材。

### 3.3 交互与异常状态（建议）

| 情况 | 系统与用户可见行为 | 恢复方式 |
|---|---|---|
| 空花园 / 无今日任务 | 显示种下目标、安排下一步或休息，不制造逾期压力 | 用户主动操作 |
| AI 思考中 | 显示处理中、可取消；旧计划仍可看 | 取消后丢弃尚未提交的提案 |
| 模型超时 / 配额耗尽 / 返回无效结构 | 提示规划暂不可用，不显示已保存；手动待办仍可用 | 保留输入草稿，可重试；服务器重试有次数与时长上限 |
| 保存失败 / 断网 | 显示待重试而非完成，暂不领奖 | 保留操作标识，恢复后核对结果再幂等重试 |
| 保存成功但返回丢失 | 查询操作结果；不再次发奖 | 展示已提交状态 |
| 旧提案遇到手动修改 | 告知安排已更新，重新计算差异 | 用户重新确认 |
| 动画失败 / 减少动态效果设置 | 用静态阶段和文字反馈 | 不阻塞操作，不补发奖励 |
| 记忆相互冲突 | 当前明确指令优先，指出冲突来源 | 用户决定是否更新长期偏好 |

### 3.4 AI 验收场景（待实现与执行）

| 用例 | 通过条件 |
|---|---|
| “一个月内准备好产品经理面试”，未说明基础和空闲时间 | 提问缺失信息，不承诺一定拿到 offer；确认后才种植和写任务 |
| 用户说每天只能投入 20 分钟 | 计划逐日负荷可解释；超过预算需明确指出并等待选择 |
| “这周没时间” | 预览短期调整，保留已有成果，不覆盖长期时间偏好 |
| “太难了”，把 1 项拆成 5 项 | 子任务更可执行；成长总份额不增加；拒绝提案后原记录不变 |
| 完成按钮重复点击 / 网络重试 | 一次完成记录、一次成长入账、一次解锁 |
| 暂停后隔一周返回 | 成长不下降；恢复不擅自把全部逾期项安排到今天 |
| AI 返回直接修改目标完成状态的请求 | 服务端拒绝无用户确认的修改 |
| 删除一条偏好后再开启新会话 | 记忆、摘要及可检索副本不再召回该偏好 |
| A 用户请求 B 用户的任务 ID | 拒绝访问，不泄露任务标题或内容 |
| 目标完成及撤销误操作 | 收藏、成长、任务与奖励资格同步，无重复植物 |
| 一个长期习惯设定时间范围、每日打卡 | 生成日期正确的实例；非计划日不算漏签；同日重复提交不重复计奖 |
| 习惯阶段到期但未达到里程碑 | 进入复盘，保留植物和积累，不自动开花或终止习惯 |
| 达成习惯里程碑后开始下一阶段 | 一份阶段收藏、同一株植物继续生长，历史成果可查 |
| 调整频率、时区或暂停恢复 | 预览影响；仅更新未来实例，过去打卡不漂移、不凭空补完成 |
| 小任务完成与阶段达成 | 前者轻反馈，后者明显变化；动画均以提交结果为准 |
| 用户离线时发生停滞 | 后台生成至站内信箱，下次打开可见；不发站外通知 |
| 候选关心生成后用户完成、暂停或关闭关心 | 投递前校验最新状态，取消不适用留言；重试不重复投递 |
| 今天之前第 3 天与第 4 天补签 | 第 3 天的已有有效实例可补签，第 4 天不计补签完成；同日重试不重复成长 |
| 用户选择“没有做”或补签非计划日 | 不记录完成、不奖励；保留现有积累，可进入调整建议 |
| 阶段建议为 30 天完成 24 天 | 用户确认前仅为提案；确认后按 24 天判断，23 天未达成；其他习惯不强套 80% |
| 连续错过 1 次、2 次，或每周三次的习惯 | 1 次不留言；2 次符合条件时只留言一次；按计划实例计数，不按自然日硬算 |
| 已留言但未回应，后台多次检查或重启 | 不新增同一停滞留言；用户可关闭；有效补签或恢复行动后重算当前状态 |
| 未注册用户首次打开 | 可完成对话、预览确认计划并种下第一株；期间清楚显示尚未保存到账户 |
| 注册取消、认证失败或迁移失败 | 回到仍有效的体验；区分注册与保存状态，允许重试，不提前删除源数据 |
| 迁移重复请求或登录已有账户 | 只迁移一次；已有内容不被覆盖；植物和奖励不重复；原游客凭证不能再访问已迁移资源 |
| 游客空间过期或请求其他游客数据 | 过期明确提示，跨主体访问拒绝；不泄露目标与对话 |
| 绘本界面在手机上减少动态效果 | 任务可读可操作，成长和休眠仍有静态反馈 |

模型、提示词、记忆策略或工具权限变更后，回归以上相关用例；权限、状态一致性与重复奖励用例必须全通过，不能被平均文案质量掩盖。计划质量由目标用户评估是否具体、可行、符合约束；样本量、评分人、验收阈值待首批试用设计确定。

## 4. 边界与红线

- 已确认：所有 AI 创建、调整计划须先展示变化，用户确认后生效；现实任务和目标由用户确认完成，AI 只辅助判断与复盘。
- 用户原始范围：2D、固定花位、少量花种，不做自由建造、复杂经营、社交；外部日历笔记和商业化放后续。
- V2 允许后台根据停滞信号生成站内关心；首版不发站外通知，不替用户执行现实行动、向他人发消息或自动支付；不因用户未登录使植物枯死或回收已有成果。
- 应用数据是事实来源，模型输出是建议；模型不能直接控制成长、奖励和完成标记。第三方内容与历史对话不能授予写权限。
- 记忆仅在授权范围使用；长期偏好与业务必需记录分别说明。日志不默认记录完整私密对话；删除应覆盖召回源和衍生摘要，备份保留策略上线前说明。
- 正式发布前必须确定账号隔离、数据保留与删除规则、模型数据处理安排和恢复验证；首发地区与适用要求尚未研究，不把草案当作合规结论。
- 用户最终确认代表自报完成，不等于产品已客观核实所有现实成果。统计和营销不得混用这两个口径。

## 5. 成功指标（可度量）

以下为建议评估方案，均无历史基线；量化业务目标、实验周期、样本量与负责人待定，不把任意阈值写成已批准目标。

| 指标 | 定义与分母 | 周期 / 数据来源 | 用途 |
|---|---|---|---|
| 连续推进率（主指标候选） | 首次确认计划的用户中，后续连续 4 个观察周每周至少确认完成一个非取消的目标任务的人数占比；窗口未满者不纳入最终分母 | 按首次确认周分 cohort；服务器完成记录，扣除已撤销记录 | 判断是否持续行动；4 周是建议观察窗口，待验证 |
| 第 4 周推进留存 | 同 cohort 中，在第 4 周确认过有效任务完成人数 / 已满 4 周的首次确认用户数 | 同上，允许中途暂停再回来 | 与连续推进率并看，避免惩罚合理休眠 |
| 计划激活 | 首次确认计划且完成第一项任务的用户 / 首次提交目标的用户 | 按 cohort，记录完成耗时 | 定位卡在澄清、确认还是执行 |
| 目标完成率 | 观察窗口内用户确认完成目标 / 同 cohort 已激活目标，按目标期限分层；暂停、归档分别报告 | 用户完成事件与成果摘要 | 长期价值，不与每日任务数混淆 |
| 调整后继续行动率 | 接受调整后，在随后 7 天内完成相关任务的用户 / 观察满 7 天的调整接受用户 | 提案与任务事件关联 | 判断调整是否有实际帮助；窗口为建议值 |
| 记忆质量 | 经用户纠错或删除的记忆条数 / 被展示或引用的记忆条数；结合原因访谈 | 记忆引用与反馈事件 | 检验“了解用户”是否准确，删除不自动等于错误 |
| 运行质量与成本 | 规划成功率、提交成功率、规划首反馈/完成耗时 p50/p95、每个活跃用户模型用量与成本 | 去重请求和服务端指标；成本按实际账单核算 | 决定模型预算与体验；目标值上线前压测确定 |

事件最小集：goal_submitted、plan_proposed、plan_confirmed、task_completed、task_completion_reversed、goal_paused、goal_resumed、goal_completed、review_opened、memory_corrected、reward_unlocked。使用事件 ID、匿名化用户标识、目标/任务 ID、提案版本、服务器时间、用户时区和结果状态去重；不向分析系统发送原始聊天和成果正文。

V2 指标分线统计：明确目标沿用目标完成率；习惯线单独统计周期内有效打卡数 / 计划实例数、阶段里程碑达成率与跨阶段继续率。暂停日和非计划日排除计划实例分母；撤销、补签和频率变更分别标记，保留原周期口径。两条线的连续推进率分别统计，汇总人数按用户去重，不把单次打卡算成整个习惯完成。

主动关心新增候选、站内投递、展示、回应、忽略和关闭事件；同时报告投递后恢复行动与关闭率，不能仅凭先后关系断言提醒有效。是否使用对照试验及样本量待确定。

新增事件：habit_created、habit_period_started、habit_checkin_confirmed、habit_checkin_reversed、habit_milestone_confirmed、care_candidate_created、care_delivered、care_viewed、care_replied、care_disabled；关联 period_id、occurrence_id、milestone_id 或 care_episode_id 去重。

V3 增加游客首次价值漏斗：体验开始 → 计划确认 → 第一株种下 → 注册开始/成功 → 账户保存成功。注册成功不等于迁移成功。匿名体验在用户选择保存后关联至账户，保留原事件标识；首次计划和首次完成不重复计数。游客首次体验转化与账户长期推进留存分别统计，临时空间过期不算用户删除账户。

验证安排建议：分别招募有明确目标和长期习惯的试用者，跑完建立、执行、遇阻、暂停恢复和两类收藏；按实际行为与访谈判断是否减少规划负担。先观察行动指标，再探索进阶 AI、外观和主题付费，不以装饰点击或在线时长代替目标推进。
