# 阶段2-9技术开发文档：遇阻拆分与历史保留

## 范围
依据 PRD V3 FR04 与第二轮「拆小」要求，在现有单步骤调整上支持把一个未完成步骤拆成1至5条建议，并逐条预览编辑；只有用户确认才更新正式计划。其他步骤、完成记录、已有计划日期与植物不丢失；原步骤日期只继承给第一条，新拆出的步骤保持待安排。不能更改已完成步骤或使用过期提案，超过单计划10条时明确拒绝并保留原计划。已完成步骤成长计数保持不变，不承诺完整份额分配；后续细化。

## 数据与兼容
调整提案增加建议及已应用步骤数组（可空，兼容旧提案与旧单文本确认），保存原文本及应用后列表；重复确认同一列表幂等，不同列表冲突。确认时先校验计划及日期基准、合并后的结构/业务约束，再于 SQLite 单事务中倒序移动目标步骤索引及完成/日期记录，防止唯一键冲突，不删历史；随后替换步骤并持久化。提案发生日期或完成状态变化时冲突。原有单文本 API 继续可用。

## 验证
自动化覆盖拆分、索引移动、完成状态及日期保留、过期冲突、超过10条、无效空行、重复确认、单文本兼容与服务重启。真实 DeepSeek 虚构目标提出拆分，确认前计划不变、用户确认后其他状态保持。页面区分原步骤与多条建议并明确确认；桌面和390px浏览器验证，根目录 verify 阶段2-9、证据包。用户数据不进入日志或前端密钥；预算沿用已确认配置。
