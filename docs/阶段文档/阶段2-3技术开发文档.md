# 阶段2-3技术开发文档：习惯周期与打卡

## 目标和范围
依据 PRD V3 FR12、3.2a 与第二轮能力图，为已确认习惯设置明确日期、时区、星期与单次完成标准；按计划日建立稳定实例，支持用户声明已执行的当日打卡、此前3个自然日补签及撤销。支持工作日等星期组合；保留实际行动日、记录时间、补签标记和历史事件。旧习惯必须由用户明确设置，不能从文字推断。后续阶段再做周期调整、暂停、成长、阶段成果确认和收藏；本阶段不自动完成、开花、清除或计奖，仅本机使用。

## 技术与数据
沿用 Python 3.12、FastAPI、Pydantic、SQLite、Next.js 与已有配置，无新依赖。增量新表：习惯阶段（一个习惯至多一个本阶段周期，包含起止日期、IANA时区、星期、完成标准快照）；计划日实例（阶段和日期唯一，计划规则在事务中生成）；状态与事件（每次实际状态变更持久化，重复请求幂等）。保留既有植物与计划；并发创建由唯一键及事务约束。当前单一主体只供本机，不宣称完成用户隔离。

## 接口与约束
- `POST /api/v1/plants/{id}/habit-stage`：明确提交开始和结束日期、时区、每周星期及完成标准，由用户主动确认；正确性及归属校验，避免重复创建；日期范围按阶段支持最多10年，避免过量写入。阶段一经创建，此阶段不支持更改。
- `GET /api/v1/plants/{id}/habit-stage`：返回阶段、阶段时区的今天、最近三日与今天的计划日实例及其完成状态；无阶段返回明确的空结果。
- `PUT /api/v1/plants/{id}/habit-occurrences/{date}`：`completed` 为严格布尔值，标记完成必须显式传 `performed: true`。只接受该阶段已生成计划实例、今天或此前三个自然日；拒绝未来日、非计划日与超期补签；重复提交不产生重复事件；已有打卡可撤销并保留历史。补签窗口按阶段时区计算，保留行动日期、记录时刻与补签标识。
- 非本人、非习惯及输入错误返回统一错误。后台不会凭到期自动确认成果。新阶段及所有实例在单事务内创建，重启可恢复。

## 界面与测试
沿用正式网页可保留切片。显示习惯周期设置，默认时区明确展示为亚洲/上海；日期和频率均由用户明确提交；显示今日及最近三日、完成与撤销、补签提示。用隔离数据库测试创建、日期和星期、跨时区、窗口边界、幂等、并发、历史、重启、归属、错误路径及旧记录兼容，运行全部回归。真实 DeepSeek 使用虚构习惯生成、用户确认、设置阶段、打卡与读回；桌面和390px浏览器验证。重启钩子同时验证目标步骤与习惯打卡持久化。最终执行 `./verify.sh Bloomate 阶段2-3`，截图、是否表、照做清单与 README 交付。

## 风险与待定
完成标准需要用户自己明确提供，不默认为达成阶段里程碑的标准；关于AI提议里程碑、阶段是否达成及成长的功能在后续子阶段实现。模型仍有不确定性，账单和数据处理规则上线前核实。高于10年周期提示拆分；本阶段没有新增必须向产品经理确认的业务决策。
