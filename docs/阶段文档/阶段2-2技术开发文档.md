# 阶段2-2技术开发文档：目标行动记录

## 目标与边界
依据 PRD V3 FR03、FR05 与第二轮能力图，先实现 goal-actions：用户在本机为已确认的目标计划步骤记录完成或撤销，刷新或重启后保留。计划中的步骤可能是一周或一阶段的描述，不能当作某天任务或由系统宣布目标完成。习惯计划日、打卡、补签、暂停、AI调整、阶段成长属于后续子阶段。本阶段保留第一轮所有功能和数据，不对外试用。

## 技术与结构
沿用 Python 3.12、FastAPI、Pydantic、SQLite、Next.js 与 pytest；已有 DeepSeek 配置不更改。后端 `backend/app/main.py`、测试 `backend/tests/`、前端 `frontend/app/`、重启检查 `scripts/restart-check.sh`。SQLite 新增表使用 IF NOT EXISTS，不覆盖旧表；不引入新依赖。运行：`cd backend && .venv/bin/python -m pytest -q`；前端 `npm run lint` 与 `npm run build`；最终在工具包根目录 `./verify.sh Bloomate 阶段2-2`。

## 数据与接口
以已确认目标植物与其不可变计划步骤为来源，读取时按已确认步骤展示默认待完成状态；用户操作时事务性写入对应步骤记录；使用 owner_id、plant_id、步骤序号唯一键、原始步骤文本与待完成/完成状态。老植物按需初始化，记录不回填假日期、不删除旧计划；重复提交不产生重复记录。后端固定主体仅供本机，暂不冒充账号隔离。查询及更改必须校验归属、目标类型；业务错误统一结构。

- `GET /api/v1/plants/{plant_id}/actions`：返回步骤列表及状态；植物不存在或不属于本人返回 404；习惯类型返回 409。
- `PUT /api/v1/plants/{plant_id}/actions/{index}`：请求 `{"completed":true|false}`，响应更新后的记录；重复同一操作幂等，索引无效404；布尔输入严格校验。

标记某个步骤完成不自动代表真实目标完成，不触发收藏或阶段成长。没有确定日期的步骤显示为“计划步骤”，不标为今日任务。人工完成和撤销是用户主动操作，由数据库事务持久化。

## 验收与测试
- mock：旧植物读取、幂等写入、完成/重复完成/撤销/重复撤销、错误输入、错误植物、习惯类型拒绝、归属过滤、重启后恢复；同时运行既有全套回归。
- 真实模型：复用现有 DeepSeek 建议生成一个虚构目标，用户确认、读取步骤、完成、重启、读回与撤销，记录用量；不以 mock 冒充。
- 页面：在目标植物下显示步骤及完成/撤销；习惯植物保持第一轮展示，桌面与390px检查。保存失败显示错误，不能展示假成功。
- 修改重启钩子，检查目标步骤完成在服务重启后仍存在；运行统一验证脚本，交付是否表及截图。

## 风险与开放项
计划步骤的粒度未必是可完成的单日任务，界面不假称今日；若用户需逐日任务和周期，后续阶段须提供明确日期与频率。旧数据兼容采用只增表的形式。金额本地预留不等于服务商硬限额，真实调用沿用已授权每月50元测试预算；服务商数据规则和账单上线前核实。本阶段无新增必须由产品经理决定事项。
