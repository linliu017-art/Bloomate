# Bloomate 第一轮双模型评测报告

状态：真实模型案例测试已运行，**人工打分和产品端完整真实冒烟待完成**；第一轮开发尚未完成。评测时间：2026-11-01（北京时间）。

## 评测范围与方法

- 两组均使用同一版园丁提示词、8 个虚构案例、非思考模式，每次输出最多 1,024 tokens；无自动重试，每个案例最多 3 次模型调用。
- 千问：`qwen3.7-flash-2026-07-15`，阿里云百炼北京地域按量 API；DeepSeek：`deepseek-flash`，厂商返回名称见原始结果。模型别名可能更新，结论只代表本次。
- 案例脚本直接调用模型 API，使用与产品相同的结构校验。另针对两模型各用一条虚构目标，通过产品后端接口真实生成、确认并读取植物，两条通过；网页真实模型流程、习惯路径及人工验收仍待验证。网页追问、刷新恢复和种植目前仅用测试模型验证过。
- 追加信息只有在模型追问后才提供，之后统一回答“其他信息不确定”。若模型提前出计划，有些补充条件实际未输入，不应据此判遗漏。E04 的更正被提前放进初始输入，不能证明真实多轮更正能力。模型在三次调用内仍未给计划记为未完成，不等于 API 出错。
- 原始记录：[首次结果](第一轮真实模型原始结果.json)；[DeepSeek E06–E08 补测](第一轮DeepSeek补测原始结果.json)。输入均为虚构，不包含密钥。

### AI 初步推荐和需优先复核项

- 暂以 DeepSeek Flash 作为第一候选：在 E01、E03、E07 的任务拆分和节奏上更符合本产品期待。但不忽略首次三次请求错误；原因仍未确定。
- 两个模型均有优先修复项：模型不应把用户未提供的期限、演讲时长等假设写成既定事实；习惯计划应明确“较短替代行动”和用户已确认的完成标准的区别，避免强制全勤语气。
- E02 DeepSeek 的未确认演讲时长、E03 千问的负荷，以及 E05 DeepSeek 的完成标准混淆标为**疑似不可接受，待产品经理判断**；不能因均值较高掩盖。
- 数值门槛、产品经理最终评分、DeepSeek API 数据处理规则和真实网页/习惯链路验收仍待完成。
