# 阶段 2-1 技术开发文档｜第一次种植

状态：开发中；依据 PRD V3（FR01、FR02、FR11、FR15）及已确认的技术适配声明。只供本机受控验证。

## 目标与边界
- 成人用户选择目标或习惯，提供背景、可用时间等信息，获得 AI 结构化计划建议；明确确认后种下一株植物。
- 计划提案、用户确认和植物持久化，服务重启后可恢复；两个入口都可验证。
- 本阶段不做账号、迁移、打卡、收藏、主动关心或对外试用。游客 7 天保留和删除尚未实现，界面不得宣称已经实现。
- 采用可保留的手机 Web 纵向切片，桌面和手机均验收。模拟模型只用于测试，界面不得将其作为真实生成冒充展示。

## 技术和配置
- Python 3.12、FastAPI、Pydantic、pytest、SQLite，服务端持久化；Next.js、TypeScript、Tailwind 和 npm 用于前端。
- 已选 DeepSeek Flash，测试期本地预留上限 50 元/月；已运行真实调用，服务商数据处理规则与实际账单待核实。预留不是供应商账单硬上限。
- `.env.example` 仅列变量名；真实密钥使用后端被忽略的 `.env`。前端不持有密钥。
- 预期目录：backend/app（接口、服务、模型、结构校验、独立 Prompt）、backend/tests、frontend、scripts/restart-check.sh；SQLite 本地数据在产品目录内。

## 数据与接口约定
- owner_id 使用本机默认主体，不视为正式登录。请求、响应及错误统一经 Pydantic 校验；错误 `{"error":{"code":"...","message":"..."}}`，不暴露堆栈。
- 持久化 conversation、generation job、proposal、confirmation、plant 及其归属和时间。提案与正式状态分离；同一提案确认和植物创建在事务中完成，重复确认不得重复种植。
- `POST /api/v1/plans`：输入类型、目标文本、背景和时间，返回持久化任务 ID；`GET /api/v1/plans/{id}`：返回 pending/running/done/error 和有效提案或统一错误。长任务可恢复、可重试但限制次数和耗时，重启后可识别中断。
- `POST /api/v1/proposals/{id}/confirm`：用户确认具体提案，返回植物及确认状态；`GET /api/v1/garden`：返回当前主体植物和计划；均需归属校验与结构验证。
- 模型调用仅在服务端独立服务中，Prompt 独立保存并约束 JSON 结构；超时、失败、初始化异常和有限重试均安全兜底，模型结果经严格校验，不可直接写入正式计划。

## 验证
- mock 自动测试覆盖两类输入、模型结构无效/超时/初始化失败、确认前无植物、确认与重复确认、重启恢复、统一错误。
- `scripts/restart-check.sh` 只用隔离的临时数据库和 mock，启动服务、写入、终止、重启、读回、清理。
- 正式前端运行类型检查、lint、生产构建；手动检查桌面和手机宽度。
- 分别对目标和习惯运行真实模型并记录用量；提供 5–10 条虚构样例供产品经理评分。
- 产品经理验收：打开网页，选目标或习惯，输入信息，查看计划，再确认种植；刷新或重启后重看植物。接口失败要有明确提示且不能产生假的成功。
