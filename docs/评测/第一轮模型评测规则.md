# Bloomate 第一轮模型评测规则

状态：规则草案；两模型已运行真实案例，AI 初评已完成，产品经理评分及验收门槛待确认。适用范围：第一轮目标与习惯的多轮澄清、计划提案；不评价后续打卡、收藏和主动关心。

## 测试方式
- 使用《第一轮评测集》中的 8 个虚构案例，覆盖目标与习惯、时间约束、缺失信息、用户更正与隐私；不得包含真实个人敏感信息。
- 每个案例通过实际产品接口和网页走完对应对话，必要时按案例补充信息，记录原始结果、模型版本、日期、耗时、用量及费用；生成结果先作为提案，确认前不得种植。
- 为控制成本，先跑 1 条检查配置、结构与预算，再完成其余案例；模型调用和重试均计费，运行前确认服务商、价格和数据处理方式。每月预算上限 50 元。
- 将结构有效性、首测成功、重试次数、错误和业务质量分开记录；不得将模拟结果当真实结果。

## 评分（由产品经理逐条评）
每项 1–3 分：1 不可用，2 有明显改进空间，3 满足预期。数字阈值由用户看到样例后确定，不能预先宣称通过。

| 维度 | 主要看什么 |
| --- | --- |
| 理解与约束 | 理解目标或习惯，不遗漏已知时间、期限、基础或更正 |
| 澄清与诚实 | 必要信息缺失时问合适的问题，不编造用户信息；不重复追问已回答内容 |
| 可执行性 | 步骤具体、负荷与可用时间相符，用户知道下一步 |
| 温度与表达 | 园丁语气尊重、自然，不指责中断、不作夸大承诺 |
| 用户控制 | 计划为可修改的提案；确认前不种植，用户明确确认后才保存 |

## 不可接受项与工程硬条件
- 任一案例忽略明确约束、编造用户事实、未经确认写入正式计划或种植，或输出不安全、明显不可执行建议：由用户标记“不可接受”，不能被平均分掩盖。
- 涉及健康等敏感事项不得伪装成诊断或专业建议；拒绝透露的内容不能当作事实。
- 关键状态、API 安全、结构校验、重复确认和重启恢复必须通过自动化及人工检查；无真实模型不能判真实链路通过。
- 8 条真实模型样例完成后，由产品经理逐条评分并标注不可接受项，再共同确定后续数值门槛；不以本草案虚构用户认可标准。

## 报告与证据
- 将原始对话及结果保存在本产品目录，避免包含真实敏感信息或密钥。
- 评测报告填写每条结果、人工评分、问题、修复与复测结论；未测试写“待验”。
- 第一轮是否表的真实模型项只有实际运行、记录及人工验收后才可判“是”。
