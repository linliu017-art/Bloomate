# 阶段2-5技术开发文档：习惯周期调整与暂停恢复

## 范围
依据 PRD V3 FR04、FR05、FR12、3.2a，提供习惯阶段频率和截止日期的调整预览与明确确认；旧历史不改，只更新确认后未来计划日。支持目标和习惯暂停、恢复；暂停保留植物、计划和完成记录，暂停日不能新打卡，恢复展示周期剩余情况且不自动延长。完成标准、时区和开始日期暂不在此子阶段变更；AI建议与阶段成果成长将在后续子阶段完善，不将手工修改包装成AI。

## 数据与接口
增量迁移：`habit_occurrences.enabled` 标示未来实例生效情况（保留未选中的未来实例与任何历史），`plant_pauses` 记录暂停起止、时区和日期；`habit_schedule_proposals` 保存旧版本、新频率/结束日期、影响摘要、状态及基准指纹。所有表按 owner 过滤；现存数据不删除。

- GET、PUT `/api/v1/plants/{id}/pause` 读取状态并按明确布尔操作暂停或恢复，重复提交幂等；暂停区间按习惯阶段时区、目标默认北京时间的自然日记录，同一天任何时候暂停，该日作为暂停日，不允许新打卡，已有记录可撤销。恢复前展示不自动延长的截止日期和未来计划日数；重复或离线恢复不篡改已有计划。
- POST `/api/v1/plants/{id}/habit-schedule-proposals` 提交选定的新星期与结束日，显示原值、新值、未来生效日期和未来计划日数；GET 查询；POST confirm / discard 明确确认或放弃。确认前任何计划、已执行记录不变。基准发生变化返回冲突；当天和历史实例保留，禁用与新增仅作用于第二天及以后，结束日期不可早于今天，范围受10年限制；新旧实例在事务中更新，旧记录不删除。时区和标准保持不变。
- 所有输入校验与统一错误，用户明确点击才变更；冲突的旧提案不覆盖新状态。重启可恢复、重复确认幂等。模型本阶段不生成日程，按项目规则复用已有真实模型链路冒烟，明确标识覆盖关系。

## 验证
针对无阶段、非本人、已完成打卡、暂停当天/多日、重复暂停/恢复、暂停后恢复、非计划日、旧计划不变、未来变更、同时有多个提案和版本冲突、撤销/重复确认、状态重启后恢复进行自动化；检查保留第一轮和2-2至2-4功能。界面桌面及390px检查、真实模型虚构习惯→确认→调整/暂停链路、重启脚本与 verify 阶段2-5。数据仍仅本机，正式用户隔离留后续。
